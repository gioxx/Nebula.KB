# Nebula Knowledge Base

Official documentation for the Nebula PowerShell modules, available at **[kb.gioxx.org](https://kb.gioxx.org)**.

The site is built with [Docusaurus](https://docusaurus.io/) and covers:

- **Modules**: [Nebula.Automations](https://kb.gioxx.org/Nebula/Automations/intro), [Nebula.Core](https://kb.gioxx.org/Nebula/Core/intro), [Nebula.Log](https://kb.gioxx.org/Nebula/Log/intro) and [Nebula.Tools](https://kb.gioxx.org/Nebula/Tools/intro), each with a stable and a development version of its documentation.
- **Nebula.Scripts** and general pages (introduction, requirements).
- **Projects**: other tools, such as Clean Mail Automation, IntuneWinAppUtil GUI and Microsoft 365 Tenant Checker.
- **Utilities**: browser-only tools (E-mail Header Analyzer, PSADT Log Viewer, Quarantine E-mail Analyzer).
- **News**: announcements and articles.

## Repository layout

| Path | Content | URL |
| --- | --- | --- |
| `docs/` | General pages and Nebula.Scripts | `/Nebula/...` |
| `modules/<Module>/` | Module documentation, **Next** version (in development) | `/Nebula/<Module>/next/...` |
| `<module>_versioned_docs/` | Module documentation, **stable** version (PowerShell Gallery) | `/Nebula/<Module>/...` |
| `Projects/` | Project pages | `/Projects/...` |
| `blog/` | News posts (`YYYY-MM-DD-Name/index.md`) | `/news/...` |
| `src/pages/` | Home page and browser utilities | `/`, `/message-header-analyzer`, ... |
| `static/` | Images and static files | `/img/...` |

Do not edit `<module>_versioned_docs/` and `<module>_versioned_sidebars/` by hand: they are generated by `Publish-ModuleDocs.ps1`.

## Module documentation versions

Each module keeps exactly two versions of its documentation:

- **Stable**: the version published on the PowerShell Gallery, served at `/Nebula/<Module>/`. It is the default.
- **Next**: the version in development, served at `/Nebula/<Module>/next/` with an "unreleased" banner.

Older versions are not kept. Write and update the documentation in `modules/<Module>/` (Next). After publishing a module release on the PowerShell Gallery, promote Next to stable:

```powershell
.\Publish-ModuleDocs.ps1 -Module Core -Version 1.3.1
```

The script removes the previous stable snapshot and creates the new one from `modules/<Module>/`. Commit the result.

`Projects/`, `docs/` and the blog are not versioned: what is merged into `main` goes online right away. Document unreleased project changes on a branch and merge it together with the release.

## Local development

Requires Node.js 24 (the version used by the deploy workflow).

```bash
npm ci          # install dependencies
npm start       # dev server with live reload on http://localhost:3000
npm run build   # production build in ./build (fails on broken links)
npm run serve   # serve the production build locally
```

Run `npm run build` before opening a PR: it catches broken links and MDX errors that the dev server may not report.

Admonitions with a title use the bracket syntax, `:::info[Title]`. The old `:::info Title` form is not supported (the site enables the Docusaurus v4 future flags).

## Deployment

Every push to `main` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): it builds the site and publishes it to GitHub Pages with `actions/upload-pages-artifact` and `actions/deploy-pages`. The custom domain `kb.gioxx.org` is configured in the repository Pages settings. Dependabot keeps the workflow actions up to date.

Search is provided by Algolia DocSearch.
